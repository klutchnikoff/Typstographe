# Production differential RGBA verification

[Protocol](../../docs/preview-stream.md). The implementation is used by the
desktop application; this is not the earlier experimental renderer substitute.

## Native pixel and transfer checks

`verification.json` was produced by `node experiments/preview-delta/verify.mjs`.
It uses the isolated release executable built by the typing-latency recipe for
`43c96bc`. Reproduction requires that executable and `corpora.json` generated by
`experiments/preview-profiling/corpus.py`. All requests use a temporary recipe
session and the built-in Article model with blank metadata from the canonical
catalogue. This yields 2/6/24 pages (the continuous-input benchmark's demo header
yields 2/7/24); the document bodies and formulas are the same.

For each corpus, verify an initial full frame, a zero-pixel refresh, a one-character
edit in the first paragraph and an independent full render. Reconstruct every
page's pixel hash and compare it, source, resolved references and 15
forward/backward/selection queries with the complete renderer. A second window
must receive a full fallback when given the first window's base. The snapshots
intentionally keep the same confirmed revision to isolate rendering comparisons;
native tests and browser recipes separately cover revision changes and reloads.

| Formulas / pages | Full RGBA packet | Edited pages | Delta packet | No-pixel refresh |
| --- | ---: | ---: | ---: | ---: |
| 10 / 2 | 16,051,455 B | 1 | 8,029,072 B | 6,422 B |
| 50 / 6 | 48,162,239 B | 1 | 8,049,405 B | 26,747 B |
| 200 / 24 | 192,646,093 B | 1 | 8,126,023 B | 103,351 B |

All three reconstructed previews, source/reference values and 45 mapping checks
match. On the 24-page article, this edit avoids 95.8% of packet bytes. A refresh
with no changed pixels still sends fresh source/reference metadata and maps.
A change affecting every page correctly falls back to sending every changed page;
there is no claim that every edit affects only one page.

STDIO uses base64 only to drive the real native renderer from Node. These are
**binary packet sizes**, not STDIO traffic sizes, production IPC timings, memory
measurements or input-latency results. No captures are recorded.

## Continuous input: measured

The [completed native input study](INPUT-RESULTS.md) compares `64b6e41` (before)
with `43c96bc` (after). All 24 sessions validate identical final text, selection,
source, pixels and navigation. On 24 pages at 100 ms/key, second-RAF p95 falls
80 → 34 ms and maximum frame gap 69 → 44 ms; the preview now updates during
fast typing. Some first-RAF metrics worsen, so the report keeps the controls and
surviving outliers explicit. This completes the run postponed while macOS was
locked; the rejected attempt contributed no sample.

Both release executables and isolated sources are retained locally. Reproduce
on an unlocked active desktop without rebuilding:

```sh
TOG_TYPING_SERIES=preview-delta caffeinate -di node experiments/typing-latency/run.mjs before
TOG_TYPING_SERIES=preview-delta caffeinate -di node experiments/typing-latency/run.mjs after
TOG_TYPING_SERIES=preview-delta node experiments/typing-latency/summarize.mjs
```

The series validates compiled frontend/core fingerprints. It does not reuse
previous raw measurements or overwrite the
[earlier before/after comparison](../typing-latency/RESULTS.md).
